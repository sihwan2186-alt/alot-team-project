# CSV·시뮬레이터·보고서 종류별 비교 분석

검토일: 2026-11-04. 원본 CSV를 다시 읽어 학습표·추론 입력·동결 모델 예측을 메모리에서 재구성했다. 재학습, 정책 변경, 기존 결과 덮어쓰기는 하지 않았다. 직접 계산한 근거는 `evidence.json`, 제어 비교 재계산은 `paired_metrics_recomputed.json`이다.

## 1. 결론

**개인 S1·S5의 모델 입력은 목적별로 분리되어 있고, 저장된 결과를 원본에서 재현할 수 있다. 그러나 전체 프로젝트가 최소 열만 저장하도록 구성된 것은 아니며, 모든 과제 조건과 전체 63실 제어가 완료된 상태도 아니다.**

- S1 학습표 152,013행과 S5 학습표 9,787행의 값·열·키를 원본으로 다시 만들었을 때 저장본과 일치했다(수치 허용오차 1e-9).
- 정답 없는 화면 입력 S1 25,363행·S5 1,635행도 재구성 결과와 일치했다. 시험 학습표보다 행 수가 많은 것은 미래 정답 결측 여부로 화면 후보를 걸러내지 않기 때문이다.
- 동결 모델로 시험 예측을 다시 계산해 저장된 예측 CSV와 비교했고, S1 MAE 2.988361점·S5 MAE 19.126120ppm을 재현했다.
- 데이터/모델 해시와 평가 기록이 일치했다. 개인 모델 학습 특징에 truth·고장 정답·미래 인원·미래 설비·에너지 사용량이 들어간 증거는 없다.
- S1은 실제 만족도 정답이 아닌 설정 환경 점수의 미래 예측이다. S5의 합성 제어 효과는 고정 대표 4실 범위다.
- W10은 43열을 저장하고 3열만 학습에 사용한다. 전체 CSV가 최소 열로만 구성되었다고 설명하면 부정확하다.
- 과거 공통 출처 해시 목록에 설비 파일 30개가 남아 있다. 실제 S1 특징 및 재구성에는 사용하지 않지만, 파일 출처 기록의 범위가 실제 사용 범위보다 넓다.

## 4. 실제 학습에 들어간 열

S1 특징 15개: `temp, humidity, co2, light, noise, occupancy, capacity, score_current, co2_change, noise_change, temp_change, co2_missing_ratio, hour_sin, hour_cos, weekday`.

S5 특징 13개: `co2, co2_lag1, co2_lag8, co2_trend, occupancy, ventilation_on, ventilation_level, volume_m3, ventilation_off_ach, ventilation_on_ach, hour_sin, hour_cos, weekday`.

학습표는 공간·기준시각·목표시각·분할의 메타데이터 4열 + 위 특징 + 해당 목표 1열만 저장했다. `target_time`은 목표가 속하는 분할·시간 경계를 검사하기 위한 메타데이터이며 회귀 입력 X에 들어가지 않는다. 추론 표에는 실제 미래 정답 열이 없다. 인원·설비는 현재 관측/상태이고 미래 값이 아니다.

S1에는 현재 환경 점수도 들어간다. 미래 점수와 강하게 연관될 수 있으나 현재 정보로 산출하므로 미래 정답 누출과 다르다. 지속값 기준선과 비교해야 하며 실제 만족도를 새로 학습했다고 해석하면 안 된다. S5의 환기 상태와 단계는 정보가 겹칠 수 있지만 설비 상태를 표현하는 현재 특징이며, 제거 효과는 별도 검증 구간 실험 없이 단정하지 않는다.

| 모델 | 학습 9/1~21 | 검증 9/22~25 | 시험 9/26~30 | 시험 MAE | 지속값 MAE |
|---|---:|---:|---:|---:|---:|
| S1 | 106,388 | 20,305 | 25,320 | 2.988점 | 4.006점 |
| S5 | 6,845 | 1,308 | 1,634 | 19.126ppm | 33.288ppm |

분할 경계와 운영 종료를 넘는 목표는 제외한다. Ridge 대체·표준화는 train에서만 fit, HGB는 시간 무작위 내부 검증을 쓰지 않는다. 검증 MAE가 지속값보다 1% 이상 개선되는 조건으로 선택하고 train+validation 재학습은 하지 않는다. 시험에는 후보 모델별 결과도 저장되어 있지만 선택 코드는 검증값만 사용한다. 이번 검토는 동결 모델의 예측을 재계산했으며 모델 재학습의 비트 단위 재현까지 시험한 것은 아니다.

## 5. 시뮬레이터 대조

공통 시뮬레이터 기본 규칙은 환기 1000/750ppm·조도350lux이고, 개인 정책이 10시 이후에 890/850ppm·조도300lux 및 목표 온도 설정을 덮어쓴다. 따라서 공통 설정 파일의 값만 보고 개인 조건 미반영이라고 판단할 수 없다. 10시 전은 공통 정책으로 워밍업한다.

개인 기준선과 예측 보조는 모두 seed 20261102·30일·동일 4실이다. 예약·재실 이벤트·고장 이벤트 파일의 해시가 같고 9/1~25 센서 파일도 동일했다. 두 실행의 저장된 validation은 valid다. 예측 보조는 9/26부터 개입한다. 이번에는 기존 시뮬레이터를 다시 30일 실행하지 않고 저장 상태·해시·성과 지표를 재계산했다.

truth·고장·에너지 자료를 **읽지 말아야 하는 곳은 모델 특징과 정책 예측 입력**이다. 제어 효과 평가에서는 실제 시뮬레이션 환경 truth, 에너지, 고장 이벤트를 읽어 초과 노출·소비전력·동일 외생조건을 검사하는 것이 필요하다. 이 평가 자료 사용을 곧바로 학습 누출로 보아서는 안 된다.

| 9/26~30 10~21시, 4실 합계 | 개인 기준선 | 예측 보조 | 변화 |
|---|---:|---:|---:|
| 재실 중 CO₂≥890인 공간·분 | 2,445 | 2,406 | -39 |
| 총전력 kWh | 62.667 | 62.532 | -0.136 |
| 환기 가동 공간·분 | 3,862 | 3,873 | +11 |

재계산값은 저장 비교 JSON과 일치했다. 공간·분은 여러 공간의 시간을 더한 값으로 단일 공간의 경과시간이 아니다. 고정 4실·단일 seed의 작은 차이이므로 전체 학교·계절·실제 장치 개선으로 일반화할 수 없다. 점검 메모·권고 화면도 장치 명령 전송 기능이 아니다.

## 7. 발견 사항과 후속 작업

1. **출처 메타데이터의 잔여 범위:** `data_contract.json/source_sha256`에는 63실 센서30개·시설목록/프로필2개 외 공통 설비상태30개가 함께 기록되어 있다(총62개). 과거 준비 단계의 추적 기록으로 보이며, 이 목록만으로 S1이 설비 파일을 학습했다고 해석하면 안 된다. 시설상태 없이 S1을 완전히 재구성해 일치 확인했다. 동결 계약을 변경하지 않고 이 분석으로 사용 범위를 명시했다. 새 버전에서는 모델별 used_source_files와 audit_only_files를 분리할 필요가 있다.
2. **W10 저장 최소화 미흡:** 43열 중 학습은 hour·weekday·lag1만 쓴다. 시설 출처·원시 집계·중복 표시 열은 추적·화면용 또는 잔여 열이다. 최소화하려면 원본 보관본, 모델 특징, 화면용 표를 별도로 정의할 수 있다. 이번 분석 요청에서는 교재 앱 입력 계약을 임의로 바꾸지 않았다.
3. **S1 후보 부족:** 25,320 시험 행 중 조건 충족12행, 405시점 중6시점뿐이다. 계산 적합성과 서비스 적합성은 다르다. 습도·기상·제습 가정 및 실제 선호 수집을 먼저 검증해야 한다.
4. **S5 범위 제한:** 63실 전체 자동 환경 제어를 충족하려면 다른59실·여러 seed·계절·고장 조건, 냉난방·조명·환기 각 목적을 별도로 검증해야 한다. 현재 학습 모델의 목표는 환기 판단을 위한 CO₂ 예측이다.
5. **유형0·실제 사용자 증거 미확보:** 고장 정의를 확보해야 조건 충족 여부를 확정할 수 있다. 실제 만족도나 선택 로그가 없으므로 개인화 효과도 확정할 수 없다.

따라서 보고서에는 **“S1·S5에 필요한 특징·시간·공간을 목적별로 선별했고 원본 재구성으로 결과를 검증했다. W10 결과 파일과 출처 추적 목록에는 학습 외 열·파일도 포함되어 있다. 63실 전체 제어와 실제 만족도 검증은 남아 있다.”**라고 설명하는 것이 현재 근거에 맞다.

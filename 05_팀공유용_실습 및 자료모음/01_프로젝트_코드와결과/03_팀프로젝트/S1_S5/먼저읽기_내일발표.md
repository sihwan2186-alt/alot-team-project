# 10월 19일 팀 검토용 S1과 S5 준비 자료

최신 범위 확정: 사용자 요청에 따라 실제 장치는 사용하지 않는다. 가상 센서·학습된 ML·가상 장치·환경 변화·재관측을 연결한 최신 실행본과 30개 검사 결과는 [시뮬레이션 완성본 검토 안내](시뮬레이션_완성본_검토안내.md)에 있다. 내일은 이 최신 안내를 먼저 읽는다. 아래 내용은 최초·중간 구현 과정의 설명으로 보존하며 실제 장치 연결을 남은 작업으로 해석하지 않는다.

김시환 담당인 S1 개인 학습 환경 추천과 김정훈 공동 담당인 S5 자동 환경 제어를 설명하기 위한 자료다. 2026년 10월 18일 Codex가 기존 파일을 검토하고 오프라인 코드를 보완했다. 내일은 아래 발표문을 먼저 읽고, 마지막 협의표를 팀원들과 확인하면 된다.

추가 구현 안내: 이 문서 아래의 기능 설명과 6개 검사는 최초 demo.py 기준이다. 후속 runtime.py에는 필수 환경 조건·시각·예약 검사와 다중 방 SQLite 이력 저장·복구를 추가했다. 최신 검증은 총 19개 통과이며, [추가구현 실행결과](추가구현_실행결과.md)를 함께 읽는다. 아래에서 다음 구현 대상으로 표시한 항목 중 필수 조건 필터, 시각 검사, 다중 방 저장, 명령 이력, 상태 재확인 함수와 끄기 후 검증은 후속 버전에 구현됐다. 실제 통신·ML·사용자 요청 해석 UI는 계속 미구현이다.

내일 발표에 추가할 문장: “이후 필수 밝기와 온습도 조건을 적용하니 같은 과거 데이터의 추천 후보가 62개에서 3개로 줄었고, 1위는 학생회관 B123으로 바뀌었습니다. 과거 데이터를 현재 데이터로 요청하면 오래된 관측으로 제외됩니다. 제어 명령과 상태도 방별로 저장해 DB를 다시 열어도 이어서 확인할 수 있게 했습니다. 자동 검사는 총 19개 통과했습니다.”

## 1. 내일 말할 발표문 약 3분

“제가 맡은 부분은 1번 개인 학습 환경 추천이고, 5번 자동 환경 제어는 정훈이와 공동 담당입니다. 1번은 사용자가 원하는 조건에 맞는 방을 골라주는 기능이고, 5번은 환경이 나쁠 때 장치를 조절한 뒤 센서를 다시 확인하는 기능입니다.

1번에서는 온도, 습도, CO₂, 조도, 소음, 현재 인원을 입력으로 사용합니다. 우선 데이터가 유효한지 확인하고 CO₂가 개인 기준인 890ppm 이상이거나 가정상 자리가 없으면 제외합니다. 남은 공간은 사용자 선호에 따라 점수를 계산하고 순위를 보여줍니다. 이번에는 습도도 점수에 넣고, 왜 그 점수가 나왔는지 항목별 감점을 확인할 수 있게 준비했습니다.

현재 비교용 입력은 실내 63실의 합성 데이터이고 소음과 인원, 정원도 가정값입니다. 따라서 실제 빈방이나 예약 가능 여부를 보장하지 않습니다. 보완한 규칙으로는 후보가 62개이고 1위가 보건관 421호입니다. 다만 이 방도 조도가 68.2lux로 낮습니다. 밤 23시 30분 데이터이기 때문에 점수가 높다는 이유만으로 바로 공부하기 좋은 방이라고 말할 수 없습니다. 밝기를 필수 조건으로 둘지, 조명 조정이 가능한 방으로 안내할지 결정해야 합니다.

5번은 먼저 CO₂ 환기를 대상으로 동작 구조를 준비했습니다. 890ppm 이상이면 켜고, 850ppm 이하이면 끄며, 그 사이에서는 이전 상태를 유지합니다. 이렇게 하면 경계에서 계속 켰다 껐다 하는 현상을 줄일 수 있습니다. 명령을 보냈다는 사실과 장치가 응답했다는 사실, 환경이 좋아졌다는 사실을 각각 구분합니다. 명령 ID가 맞는 장치 응답을 확인하고, 5초 안에 응답이 없으면 상태 미확인으로 처리합니다. 정상 응답 후 8분이 지나면 CO₂를 다시 확인하는 구조입니다. 5초와 목표값은 검토용 설계값입니다.

이번에 중복 요청, 다른 명령의 응답, 응답 지연, 수동 조작, 결측 입력, 재확인 시점을 포함한 자동 검사 6개를 통과했습니다. 실제 장치 통신이나 실제 환기를 수행한 결과는 아닙니다. 시나리오에 있는 ML 모델도 아직 연결하지 않았고 현재는 설명 가능한 규칙 기준선입니다.

내일은 정훈이와 제어 판단과 장치 인터페이스의 분담을 확정하고, 선강이에게 인원과 혼잡도 입력 형식을, 민재에게 센서 이상 시 자동 제어를 막을 신호를 맞추고 싶습니다. 공통 방 식별자, 단위와 시각 형식도 같이 맞추면 각자 구현을 연결할 수 있습니다.”

## 2. S1 추천 설계와 실제 준비된 부분

흐름: 사용자 선호 → 관측 유효성 검사 → 후보 제외 → 6종 환경 비용 계산 → 가중 점수 → 순위와 항목별 근거.

| 항목 | 이번 기본 가중치 | 비용 0에 가까운 조건 |
|---|---:|---|
| 소음 | 0.35 | 30dB 근처 또는 이하 |
| 혼잡도 | 0.20 | 가정 인원 / 가정 정원이 낮음 |
| CO₂ | 0.20 | 400ppm 근처 또는 이하 |
| 온도 | 0.10 | 23°C에 가까움 |
| 습도 | 0.10 | 50%RH에 가까움 |
| 조도 | 0.05 | 300lux 이상 |

점수 = 100 − 항목별 가중 감점의 합. 소음 비용=(dB−30)/30, CO₂ 비용=(ppm−400)/490, 온도 비용=|°C−23|/7, 습도 비용=|%RH−50|/30, 조도 비용=(300−lux)/300이며 각각 0~1로 제한한다. 혼잡도 비용=인원/정원이다. 가중치는 개인 선호를 반영하는 예시이며 공식 기준이나 학습된 모델 파라미터가 아니다.

이전 모의 예제와 달리 습도를 추가하고 가중치를 바꿨으므로 점수와 순위도 달라졌다. 이전 보고서의 88.1163점과 이번 86.7496점을 같은 설정의 결과로 섞지 않는다.

| 이번 순위 | 공간 | 점수 | 확인할 약점 |
|---|---|---:|---|
| 1 | 보건관 421 | 86.7496 | 조도 68.2lux, 실제 예약·정원 미확인 |
| 2 | 도서관 B101I | 85.6842 | 조도 55.5lux, 실제 예약·정원 미확인 |
| 3 | 학생회관 410 | 84.4290 | 조도 61.8lux, 실제 예약·정원 미확인 |

점수는 만족도나 추천 정확도 백분율이 아니다. 현재 필수 제외는 입력 오류·CO₂·자리 부족이고 온습도·조도는 감점 조건이다. “밝은 방만”처럼 사용자가 반드시 요구한 조건의 필터와 사용자 요청 해석 UI는 다음 구현 대상이다. 후보가 없으면 빈 목록을 반환하고 조건 완화나 환경 조정 안내를 해야 한다.

소음·인원은 기존 난수 가정이고 정원은 모든 방 8명이다. occupancy=0/1을 실제 인원 수로 해석하지 않는다. 프로토타입은 고정 스냅샷 비교용이며 실시간 데이터 신선도 검사와 방별 최근 관측 선택은 운영 연결 시 추가한다.

## 3. S5 환기 제어 설계와 실제 준비된 부분

흐름: 유효한 CO₂ → 수동 조작 여부 확인 → 현재 확인 상태와 목표 비교 → 명령 ID 발급 → 장치 ACK → 8분 후 재측정 → 목표 도달 여부.

| 상황 | 구현된 모의 동작 |
|---|---|
| 꺼짐, CO₂=890 | 켜기 명령 생성 |
| 켜짐, CO₂=850 | 끄기 명령 생성 |
| CO₂=870 | 이전 확인 상태 유지 |
| 기존 명령 응답 대기 | 새 명령 생성 차단 |
| 다른 command_id 응답 | 상태 변경 없이 무시 |
| 5초 경계까지 ACK 없음 또는 늦은 ACK | 상태 미확인, 후속 자동 명령 차단 |
| ACK의 실제 상태가 요청과 다름 | 상태 미확인, 확인 필요 |
| 수동 조작 중 또는 오래된 센서 입력 | 자동 요청 차단 |
| 켜기 ACK 후 480초 전 | 재측정 대기 |
| 켜기 ACK 후 480초, CO₂≤850 | 모의 목표 도달 |
| 켜기 ACK 후 480초, CO₂>850 | 목표 미도달, 검토 필요 |

타이머는 실제로 기다리는 대신 함수에 경과 초를 넣어 검사했다. 센서 신선도는 fresh 플래그를 호출자가 전달하며 실제 시각 비교는 아직 연결하지 않았다. ACK 5초는 검토용 값이고, 8분은 학번 산식 5+q=8을 재확인 간격으로 적용한 설계 가정이다. 8분 집계 기능을 구현했다는 뜻은 아니다.

현재는 한 방의 메모리 상태만 관리한다. 프로그램 재시작 시 상태 복원, 타임아웃 뒤 실제 상태를 조회해 복구하는 절차, 다중 방 제어, MQTT 연결, 장치 측 중복 명령 처리와 ACK 영속 저장은 미구현이다. 끄기 후 검증, 온습도·조명·외기 조건·개인 선호 제어도 다음 범위다. PUBACK는 브로커 수신 확인이므로 장치 동작 ACK로 대체하지 않는다.

## 4. 팀원들과 확정할 내용

아래는 협의 제안이며 합의된 분담이 아니다.

| 협의 상대 | 가져갈 제안 | 내일 결정할 사항 |
|---|---|---|
| 김정훈 S2·S5 | 김시환은 환경 조건·제어 판단·재확인, 김정훈은 시설/예약 입력과 장치 명령·ACK 인터페이스 중심 | 실제 공동 분담, 가능한 장치 종류, 수동 조작 우선 처리 |
| 최선강 S3·S6 | 실제 인원과 예측 인원을 별도 필드로 받음 | current_people와 predicted_people의 정의·시각·오차, 에너지 요청과 환경 요청 충돌 정책 |
| 이민재 S4·S6 | 센서 오류 시 추천·자동 제어를 차단할 상태 전달 | sensor_valid·이상 유형·심각도와 해제 조건 |
| 전원 | 공통 방 키와 측정 단위 통일 | team_id/building/room 매핑, observed_at 시간대, 데이터 유효 시간 |
| 전원 | 조도 300lux를 기본 감점으로만 둔 현재 설계 검토 | 사용자 필수 조건으로 제외할지, 조명 제어 가능 시 조건부 추천할지 |
| 전원 | 규칙 기준선을 먼저 연결하고 ML 교체 | 환경 상태 정답 정의, 학습 데이터 확보, 독립 평가 방식 |

S1은 현재 환경 선호 순위, S2는 목적·시설·예약 적합성, S3는 미래 혼잡도, S4는 이상 신호 제공 역할로 연결한다. S6의 에너지 요구가 S5의 환기 요구와 충돌할 때 우선순위는 팀이 정해야 한다.

## 5. 연결용 입력과 출력 제안

관측 입력은 team_id, building, room, observed_at, temp(°C), humi(%RH), co2(ppm), light(lux), noise_db(dB), current_people(명), capacity(명), sensor_valid, data_origin을 포함하도록 제안한다. 예약 가능 여부는 true/false/unknown을 구분하고, 누락을 가능으로 취급하지 않는다. 실시간 연결에서는 시간대가 있는 ISO 8601 시각을 사용한다. 기존 합성 시각에는 시간대가 없으므로 실제 현재 시각으로 바꾸어 쓰지 않는다.

추천 출력은 공간 키, 순위, 점수, 항목별 감점, 제외 이유, 관측 시각, 가정·예약 미확인 안내를 전달한다. 현재 코드에는 관측 시각 출력과 예약 검사가 연결되지 않았다.

제어 명령은 command_id, 공간 키, actuator, desired_state, issued_at, expires_at을, 장치 응답은 command_id, 공간 키, actual_state, status, ack_at을 포함하도록 제안한다. 운영에서는 command_id와 방 키를 함께 확인한다. 현재 코드는 단일 방이므로 command_id만 확인한다. 재측정은 명령 전후 관측 ID와 목표 도달 여부를 함께 저장하도록 설계한다.

## 6. 실행과 검토 순서

프로젝트 루트의 PowerShell에서 실행한다. Python 표준 라이브러리만 필요하다.

```powershell
python .\내일검토_S1_S5\demo.py
```

실행하면 이 폴더의 demo_results.json을 갱신한다. 원본 CSV·DB·기존 보고서는 수정하지 않는다. 결과 파일에는 전체 순위, 제외 목록, 항목별 감점, 입력 해시와 검사 성공 여부가 있다. 2026-10-18 Codex 실행 환경 Python 3.14.3에서 검사 메서드 6개 통과, 후보 62개·제외 1개를 확인했다.

내일 검토 순서는 발표문 읽기 → demo.py 실행 → 결과의 1위 감점 확인 → 낮은 조도 문제 설명 → S5 경계·타임아웃 설명 → 팀 협의표 확인이다. 본인 실행 화면과 팀원의 실제 피드백은 직접 확보한 뒤 보고서에 추가한다.

## 7. 파일 검토 범위와 남은 자료

전체 작업 폴더를 순회해 관련 자료 269개를 추출·목록화했다. DOCX 본문, 텍스트·코드·CSV·JSON·SQL, ZIP의 텍스트 파일을 추출하고 DB는 읽기 전용 스키마·건수·외래키 검사를 했다. PDF는 기존 추출 텍스트를 사용했다. 구형 7장 함수.ppt는 해시·목록만 확인했고 본문은 읽지 못했다. 가상환경·외부 패키지·캐시·이미지의 시각 검토는 이번 범위에 포함하지 않았다. 모든 파일을 새로 실행하거나 모든 화면을 검토한 것은 아니다. 상세 범위는 자료검토목록.json, 추출 자료는 자료추출본문.txt에 있다.

근거는 시나리오_ver2.docx, 통합보고서_작성본/통합보고서_본문.md, 시나리오_모의검증의 코드·CSV·results.json, 주차별 코드·보고서·강의 추출문이다. W07 제공 입력과 실제 ML 비교 지표는 여전히 미확보다. 실제 추천 만족도, 장치 제어 성공률과 에너지 절감률도 미측정이다. 이번 코드는 Codex 작성·실행 결과이며 학생의 과거 수행이나 팀원의 기여로 바꾸어 기록하지 않는다.

# S1과 S5 추가 코드 사용 안내

최신 실행은 `python .\내일검토_S1_S5\run_system.py` 또는 `run_review.cmd`다. 실제 장치 없이 ML 학습과 동적 환경 시뮬레이션까지 실행한다. [최신 검토 안내](시뮬레이션_완성본_검토안내.md)를 우선 참고한다. 아래 run_extended.py와 API 예시는 중간 버전 및 개별 함수 사용 설명이다. 실제 장치 통신은 구현 범위에서 제외했으며 아래의 실제 연동 언급은 선택적 외부 확장 설명이다.

기존 발표 자료를 보완하는 오프라인 구현이다. 원본 보고서·W06 DB·센서 CSV를 변경하지 않고 표준 Python 라이브러리로 실행한다.

## 한 번에 확인하기

프로젝트 루트에서 다음 명령을 실행한다.

```powershell
python .\내일검토_S1_S5\run_extended.py
```

현재 컴퓨터에서는 PowerShell 스크립트 실행 정책 때문에 ps1 실행이 차단되는 것을 확인했다. 위 Python 명령 또는 같은 폴더의 `run_review.cmd`를 사용하면 된다. 시스템 설정은 변경하지 않았다. 실행이 허용된 다른 환경에서는 `실행하기.ps1`도 같은 검사를 실행하고 결과 문서를 터미널에 보여준다.

- runtime.py: 필수 조건을 포함한 추천과 SQLite 기반 환기 제어
- test_runtime.py: 추가 검사 13개
- run_extended.py: 기존 검사 6개와 추가 13개, 과거 데이터 비교·제어 시연을 묶어 실행
- 추가구현_실행결과.md: 사람이 읽는 최신 실행 결과
- extended_results.json: 전체 비교 순위·제외 이유·명령·장치 모의 응답·감사 이력
- extended_test_log.txt: 검사별 성공 여부

## 추천 함수 연결 예시

아래 코드는 이 폴더의 Python 파일에서 실행하는 예시다. 환경값과 예약 가능 여부는 시험용 입력이다.

```python
from runtime import recommend_live

now = '2026-10-18T10:00:00+09:00'
observation = {
    'team_id': 'team02', 'building': '시연용가상건물', 'room': 'A',
    'observed_at': now, 'sensor_valid': True,
    'temp': 23, 'humi': 50, 'co2': 600, 'light': 400,
    'noise_db': 35, 'current_people': 1, 'assumed_capacity': 8,
    'reservation_available': True, 'data_origin': 'manual_test_fixture',
}
result = recommend_live(
    [observation], now, min_light=300, max_noise=40,
    temperature=(20, 26), humidity=(40, 60),
    require_reservation=True, max_age=120,
)
print(result)
```

사용자가 반드시 원하는 조건은 함수 인수로 전달한다. 조건을 해제할 때는 min_light·max_noise·temperature·humidity에 None을 쓴다. max_age는 초 단위이며 기본 120초다. 예약 확인을 필수로 설정하면 누락·unknown·False는 모두 제외한다. 모든 시각은 시간대를 포함해야 한다. same-time 중복 중 내용이 다르면 해당 방의 최신 관측을 추천에서 제외한다.

공통 키는 team_id/building/room이다. 기존 team01과 문서의 2팀 표기는 자동 변환하지 않는다. 실제 정원 확보 후 assumed_capacity에 실제 정원을 매핑하고 출처도 표시해야 한다. 이 입력 명칭은 기존 가정 데이터와의 호환을 위해 유지했다.

## 제어 함수 연결 예시

```python
from runtime import Controller

key = ('team02', '시연용가상건물', 'A')
c = Controller('my_mock_control.db')  # 별도의 작업 DB를 생성한다.
try:
    # 실제 연동에서는 인증된 새 장치 상태 조회의 결과를 사용한다.
    c.reconcile(key, False,
                '2026-10-18T10:00:00+09:00', '2026-10-18T10:00:00+09:00')
    cmd = c.request(key, 1000,
                    '2026-10-18T10:00:00+09:00', '2026-10-18T10:00:00+09:00')
    if cmd['status'] == 'mock_command_created':
        c.ack(key, cmd['command_id'], True, '2026-10-18T10:00:02+09:00')
        print(c.verify(key, cmd['command_id'], 840,
                       '2026-10-18T10:08:02+09:00', '2026-10-18T10:08:02+09:00'))
finally:
    c.close()
```

명령 생성 직후 장치가 켜졌다고 확정하지 않는다. ACK는 동일 방 키·명령 ID·불리언 실제 상태를 검사하며 송신 후 5초 경계부터 시간 초과로 본다. 재측정은 수신 시각이 아닌 관측 시각이 ACK 후 480초 이상인지를 확인한다. 기본 값은 팀 검토가 필요한 설계 가정이다.

`tick(key, now)`는 호출 시 시간 초과를 처리한다. 실제 주기 실행은 외부 스케줄러가 필요하다. `set_manual(key, True, now)`는 미완료 자동 명령을 취소 처리하고 상태를 미확인으로 바꾼다. 자동 복귀 후에는 `reconcile`로 장치 상태를 새로 확인한다. 전송 중인 물리 명령의 실제 취소는 별도 장치 인터페이스 작업이다.

SQLite에는 rooms, commands, audit를 저장한다. 생성된 command_id는 UUID를 사용하며 방별 대기 명령은 하나로 제한한다. 이력을 덮어쓰거나 기존 W06 스키마를 변경하지 않는다. 운영 서비스의 인증·장치 ID 검증·프로세스 재접속·데이터 보존 정책까지 구현한 것은 아니다.

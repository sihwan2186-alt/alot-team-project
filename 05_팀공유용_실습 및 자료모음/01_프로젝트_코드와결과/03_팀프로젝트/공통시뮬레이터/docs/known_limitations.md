# 알려진 한계

- 실측으로 보정한 디지털 트윈이 아니다. 실제 시설 성능·날씨·행동의 통계 분포를 재현한다고 검증되지 않았다.
- 사용자 제공 호실 목록을 사용한다. 원본 7개 스크린샷의 독립 재판독 및 실제 층·면적·정원 확인은 하지 않았다.
- 단일 구획 완전 혼합 모델로 창문·복도·공간 간 이동·다중 벽체 축열·인간 활동별 발열을 정밀하게 모델링하지 않는다. 유효 열용량에 종합 축열을 포함한다.
- 예약 취소는 생성 시점에 확정된다. 변경·취소 이력과 예약 생성 API는 없다. 실제 사용자 식별정보는 생성하지 않는다.
- walk-in은 이벤트 기반 단순 확률 과정이다. 사람이 예약 시작·종료에 완벽히 맞춰 움직이지 않는 효과는 제한적으로만 반영한다.
- 센서 고장 종류 네 가지는 현재 CO₂ 채널에 적용한다. 다른 센서의 고장, 복수 동시 고장, 통신 지연·센서 교체는 확장 대상이다.
- v0.2의 환경 이상 정답은 설정한 truth 임계 범위 이탈이다. 주입 원인·회복 상태와 별도이며 임계값 자체는 운영·보건 기준으로 검증되지 않았다. 회복은 고장 종료와 관련 변수의 이상이 시간상 연결된 구간이며 인과관계를 입증하지 않는다.
- 제어는 규칙 기반이며 최적 제어/MPC/강화학습이 아니다. 조명은 ON/OFF 수준이다. 외기 온도는 v0.2 열수지 CSV에 기록한다. 다른 외기 변수는 엔진으로 재계산할 수 있다.
- 원시 경로의 `_1min`, 집계 경로의 `_5min` 이름은 CLI 출력 간격을 바꿔도 유지된다. 비기본 간격은 manifest와 aggregation.json으로 구분한다.
- CSV는 일별이며 날짜별 집계는 하루 센서 자료를 메모리에 올린다. 검증기는 이벤트 조회를 메모리에 보유한다. 장기·다캠퍼스 규모에서는 SQLite/Parquet 등으로 전환을 검토해야 한다.
- 시작일 이전 예약 생성 시각은 가능하다. 시뮬레이션 종료 이후 예약은 만들지 않는다. 초기 환경 상태는 공통 가정값이므로 첫날 초반은 초기화 과도구간으로 해석한다.
- 다른 Python 버전·플랫폼 간 부동소수점 문자열까지 동일한 결과는 별도 검증하지 않았다. 현재 실행 환경의 재현성만 실제 테스트한다.
- 생성 중 재개, 원자적 CSV 묶음 커밋, 대시보드, 실제 ML 모델·챗봇은 포함하지 않는다. 불완전 실행은 manifest 상태로 구분한다.

## 다음 단계 추천
먼저 학교에서 허용된 절차로 실제 시설 메타데이터와 익명 집계 관측을 확보해 프로필·수요·환경 계수를 보정한다. 이후 시간 분할을 고정하고 단순 기준모델부터 평가한다. 합성 데이터의 높은 F1-score가 실제 센서의 일반화 성능을 보장하지 않으므로, 실측 외부 검증을 별도로 수행해야 한다.

- v0.2 현열 모델은 상수 COP·종합 UA·단일 유효 열용량을 쓴다. 실제 건물 보정, 일사 열획득, 제습 잠열, 복사·다중 구획 모델은 남은 한계다.

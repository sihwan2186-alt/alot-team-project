# S1 v2 · 가상 상황별 실험

2026-11-04 실행 완료. 실제 센서·학생 만족도·예약 자료를 사용하지 않았다. 기존 v1 데이터·모델·시험 결과를 보존하고 이 폴더에 별도 생성·학습했다. 결과는 `artifacts`에 있다.

## 확인 방법

루트에서 `실습시작.ps1` 실행 → 학생 화면 → 왼쪽 **실험 데이터: 상황별 가상 실험** → 가상 상황·시각·공간 선택. 기존 30일 자료와 S5 관리자 화면도 그대로 확인할 수 있다.

v2의 추천은 현재 조건 충족 공간을 **현재 환경 점수순**으로 표시한다. 다음 8분 예측값은 참고 정보다. 검증 구간에서 예측 모델의 추천 순위 개선이 확인되지 않아 예측점수 정렬은 채택하지 않았다. 조건 충족 공간이 없을 때는 별도 접힌 영역에 미충족 이유와 함께 참고 공간을 보여주며, 추천으로 세지 않는다.

## 습도 원인 점검

공통 엔진의 절대습도는 외기 유입·재실자 수분 발생·냉방 시 제습을 반영하고 온도별 포화 수분량으로 상대습도를 계산한다. 기존 외기 평균 습도65%와 냉방에서만 적용되는 분당0.002 제습 계수가 습도40~60%라는 선호 조건과 맞지 않는 경우가 많았다. 현재 근거로 계산 오류나 코드 버그라고 단정하지 않았다.

따라서 원래 습도값을 낮춰 덮어쓰거나 추천 범위를 완화하지 않았다. 같은 난수 조건에서 외기 평균 습도45%와65%를 별도 시나리오로 생성했다. 각 실행의 센서 습도 중앙값을 평균하면 건조 외기46.12%, 다습 외기64.64%였다. 고온다습 상황에서는95.72%로 높게 나왔으며, 이는 의도된 스트레스 상황이다. 실제 기상·건물에 보정된 수치는 아니다.

## 실험 설계

- 공통 v0.2의 환경·열수지·소음·센서 엔진을 재사용했다. 환경/센서/설비 규칙과63실 가상 프로필은 기존 자료를 읽고 메모리에서 상황 조건만 변경했다. 개인 제어의 ≥890ppm 켜기·≤850ppm 해제, 최소가동5분은 기존 PersonalPolicy를 재사용한다.
- **공통 30일 예약 시뮬레이션을 그대로 재실행한 실험은 아니다.** 이 실험의 재실은16분마다 가상 정원 대비 이항분포로 생성한다. 별도 난수 스트림을 사용해 같은 seed의 상황 간 재실·센서 난수를 맞췄다.
- 63실 전체, 09~10시 워밍업, 10~13시 관측. 하루 전체·주말 전체·계절 일반화 검증은 아니다.
- 6개 상황: 건조 외기, 기존 다습 외기, 혼잡, 일부 조명 고장, 센서 결측, 고온다습. 일반적인 물리 현상을 가정한 인위적 시험 조건이며 교수의 미확보된 '유형0'을 구현한 것은 아니다.
- train seed1201/1202, validation2201, test3201/3202. 날짜도 train9/2·9/16, validation9/23, test9/27·9/29로 분리했다. 공간은 동일63실로, 미관측 공간 일반화는 아니다.
- 시나리오·seed·run_id·future_eligible은 모델 입력이 아니다. 실제 미래 정답은 학습/평가 표에만 저장한다. 화면 입력은 정답 없이 만들며, 알려진 실험 종료13시 이후 목표는 표시하지 않는다.
- 기존 개인 선호·가중치·8분 집계·Leq·조건 검사는 유지했다. 여러 실제 학생의 선호를 학습한 모델은 아니다.
- 실행 전 `plan.json`을 저장했다. 11개 기본 특징과15개 전체 특징, Ridge와HGB 두 복잡도를 검증 MAE로 비교했다. 지속값보다1% 이상 개선될 때만 복잡한 모델을 채택하며 시험으로 모델을 선택하거나 재학습하지 않았다.

## 결과

원시 센서340,200행을 생성했다. 학습15,492행·검증7,746행·시험15,492행이다. 완전한 다음8분 창과 미래 조건 평가가 가능한 행을 사용했다. 미래 결측으로 인한 학습표 선별과 정답 없는 화면 입력을 구분했다.

| 모델 | 검증 MAE | 새 시험 MAE |
|---|---:|---:|
| 지속값 | 4.216 | 4.534 |
| Ridge 기본 특징 | 3.944 | 선택에 쓰지 않아 별도 최종 비교 생략 |
| HGB 기본 특징 | 2.899 | 동일 |
| **HGB 전체 특징** | **2.850** | **2.890** |
| HGB 전체 특징·작은 트리 | 2.903 | 선택에 쓰지 않아 별도 최종 비교 생략 |
| 동결 v1을 같은 새 시험에 적용 | 모델 선택 대상 아님 | 4.235 |

v1과v2는 학습 분포·행 수가 다르므로 순수 알고리즘 우열 실험은 아니다. v1의 원래 시험 MAE2.988과v2의2.890만 직접 비교해 개선률을 계산하면 안 된다.

| 시험 상황 | v2 점수 MAE | 조건 충족 후보가 있는 시점 |
|---|---:|---:|
| 건조 외기 | 3.121 | 42/42 |
| 기존 다습 외기 | 3.137 | 14/42 |
| 혼잡 | 1.707 | 26/42 |
| 일부 조명 고장 | 3.124 | 42/42 |
| 센서 결측 | 3.104 | 42/42 |
| 고온다습 | 3.179 | 1/42 |
| 전체 | 2.890 | 167/252 (66.27%) |

조건 미충족 시점85개에는 조건이 부족한 참고 공간을 별도로 제시할 수 있었다. 이는 추천 가능률100%를 뜻하지 않는다. 저조도·결측 상황에서도 다른 정상 공간이 있어 후보가 남을 수 있으며, 모든 공간이 정상이라는 의미도 아니다.

## 추천 순위 채택을 보류한 이유

점수 MAE와 추천 품질을 구분했다. 검증 시 예측점수 정렬의 순위 손실은6.900점으로 현재점수 정렬4.527점보다 컸고, 추천한 공간의 미래 조건 위반율도22.5% 대20.0%로 나빴다. 따라서 모델 선택은 유지하되 추천 정렬의 운영 채택은 보류했다. 이 보수적 채택 검토는 원래 MAE 선택 규칙과 별도이며 `operational_decision.json`에 기록했다. 기준은 검증 결과이며 시험 결과로 대체 모델을 선택하지 않았다.

시험에서는 예측점수 정렬의 순위 손실5.893점으로 현재점수7.288점보다 작았지만 미래 조건 위반은34.73% 대26.35%로 오히려 높았다. 시험 결과가 일부 좋게 나와도 검증에 따른 보류 결정을 뒤집지 않았다. 현재 화면은 조건 충족 공간 안에서 현재점수 정렬을 유지한다. 현재 조건 충족은8분 뒤 모든 조건 충족을 보장하지 않는다.

가상 상황을 다양화해 쾌적 조건에 해당하는 데이터를 확보한 것은 데이터 커버리지 보완이다. 기존 v1의6/405와 새 상황의167/252는 분포·기간·생성기가 달라 직접 비교할 성능 개선 지표가 아니다.

이번에는 DOCX 보고서를 덮어쓰지 않았다. 이 문서가 v2 실험의 별도 보완 설명이다. 실제 선호·실측 효과를 주장하지 않으며 향후에는 전일 시간대·더 많은 seed·다양한 재실 변화 및 미래 조건의 별도 예측 검증을 새 버전으로 진행할 수 있다.

`run_experiment.py`는 결과가 존재하면 덮어쓰지 않고 중단한다. 재현 실험은 새 버전 사본에서 실행한다. 읽기 중심 검증 명령은 `verify_experiment.py`, 화면 검증은 `verify_app.py`다.
